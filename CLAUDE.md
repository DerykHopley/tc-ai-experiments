# Embedding model comparison

Compares how embedding models relate 68 historical figures by their biographies. `README.md` covers setup, running and the file layout. **Read `FINDINGS.md` before analysing results or planning next steps**: it holds the results so far, method choices, the Marie Curie analysis and open ideas.

## Working with the user

- Turing College student, coming from Python and learning TypeScript. Python comparisons help (f-strings vs template literals, pandas vs plain arrays). Explain *why* a change is better, not just what changed.
- The course repo is `../1-2-development-environment-api`. This project started as its exercise 26.
- `npm start` calls the embeddings API once per model (a fraction of a cent per run). Running it to verify a change is fine. For page-only changes, re-render from saved data instead (below).

## Gotchas

- **`@thi.ng/tsne` keeps the input's dimensions in its output**, so 3072-D embeddings come out 3072-D. `tsne2d` in `src/lib/tsne-scatter.ts` keeps the neighbour probabilities computed from the full vectors, then overwrites internal fields (`dim`, `points`, `steps`, `gains`, `gradient`, `ymean`, `opDist`, `opDivN`, `opSub`) to lay out in 2D. The package is alpha and pinned at 0.1.75; after any upgrade, check this function first.
- **Vectors are scaled to length 1 in `getEmbeddings`**, so the dot product is cosine similarity for every model.
- **OpenRouter guardrails can block a model** (404 mentioning "guardrail"). `Promise.allSettled` skips it with a warning and the page lists it; the user configures guardrails at https://openrouter.ai/workspaces/default/guardrails.
- **Embeddings vary slightly between API calls**, so neighbour lists can drift between runs even with the fixed t-SNE seed.
- **`data/historical_figures_tags.json` was hand-assigned by Claude** (one field per person, keyed by figure id). Treat it as the user's to edit; flag judgement calls rather than silently changing them.
- npm's `allowScripts` blocks esbuild's postinstall here; `tsx` still works without it.

## Changing the page

The page is generated by `src/lib/model-comparison-page.ts` and embeds all its data as JSON, so it can be rebuilt without API calls. From the project root:

```sh
cat > src/.rerender.ts <<'EOF'
import fs from 'fs';
import { renderComparisonHtml } from './lib/model-comparison-page.ts';
const file = 'output/model-comparison.html';
const json = fs.readFileSync(file, 'utf8').match(/<script id="data" type="application\/json">([\s\S]*?)<\/script>/)![1];
fs.writeFileSync(file, renderComparisonHtml(JSON.parse(json)));
EOF
npx tsx src/.rerender.ts; rm src/.rerender.ts
```

This only works when the data shape is unchanged; after changing `compareModels` or the panel data, run `npm start`.

**Look at every visual change before reporting it done.** Firefox is installed as a flatpak and can screenshot headless (the viewport only, so use a tall window and crop with Python's PIL):

```sh
mkdir -p /tmp/ff-profile
flatpak run --filesystem=/tmp --filesystem="$PWD/output:ro" org.mozilla.firefox --headless --no-remote \
  --profile /tmp/ff-profile --window-size=1200,3300 --screenshot /tmp/page.png "file://$PWD/output/model-comparison.html"
```

To open the page for the user, run `xdg-open output/model-comparison.html`. Don't use `flatpak run ... org.mozilla.firefox <url>` for this: it failed to load the file once, most likely because the URL went to an already-running Firefox that lacked the `--filesystem` grant. The headless screenshot above is unaffected because `--profile` starts a separate instance.

To capture a state, copy the HTML to `/tmp`, replace the final `select(selected);` with e.g. `select('Marie Curie');`, and add `data-theme="dark"` to `<html>` for dark mode.

Charts follow the `dataviz` skill; load it before chart changes. Colours are CSS custom properties at the top of the page, with separate light and dark values. The series blue (`#2a78d6` light / `#3987e5` dark) and the heatmap ramps were checked with its palette validator; re-validate any new colour.
